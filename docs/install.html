Setup

Install Sidelong

Four steps, about three minutes. No API key, no account, no .env file — the port and token are generated locally on first launch.

Before you start

RequirementNotes
Claude CodeWith HTTP hook support. Verified on 2.1.119 — check with claude --version.
Node.js 20+For the build and the CLI tools.
Windows 11Tested. macOS and Linux are best-effort and untested — the code is portable, but always-on-top behaviour and notifications are the likely rough edges.
VS CodeOptional. Only the bridge extension needs it.

Build and launch

git clone https://github.com/gamith24/sidelong-claude-code-status-bar.git
cd Sidelong
npm install
npm run build
npm start

First launch writes a config file with a fixed port (47821) and a persistent random 64-character token. Both stay stable across restarts, because they get written into your Claude Code settings in the next step.

Running this from a terminal inside VS Code? VS Code sets ELECTRON_RUN_AS_NODE=1, which makes the Electron binary behave as plain Node. The app will exit without ever opening a window. Clear it first:

# PowerShell
Remove-Item Env:\ELECTRON_RUN_AS_NODE

# bash
unset ELECTRON_RUN_AS_NODE

Install the hooks

From the app: expand the bar → Hooks → Install. Or from the CLI:

node tools/install-hooks.mjs install                  # all projects (recommended)
node tools/install-hooks.mjs install --scope project # this repo only
node tools/install-hooks.mjs status

User scope is the default — ~/.claude/settings.json, so one install covers every project. Per-project means no overlay in whichever repo you forgot, which rather defeats the point.

It is safe to run on an existing settings file. The installer merges into existing hook arrays without clobbering them, is idempotent, backs the file up once before its first change (settings.json.sidelong-backup), and never writes managed policy settings. Uninstall removes only entries whose URL starts with Sidelong's own base URL.

Verify

Inside Claude Code, list the installed hooks:

/hooks

And confirm the receiver is live (token is in your config file):

curl -H "X-Sidelong-Token: <token>" http://127.0.0.1:47821/health
# {"ok":true,"protocolVersion":1}

Now give Claude Code a task. The bar should move within a second.

Sessions already running are not retrofitted. Hooks are read from settings when a session starts, so restart any session that was open before you installed.

Add the VS Code bridge — optional

npm run package -w sidelong-claude-status-bar
code --install-extension extensions/vscode-bridge/sidelong-claude-status-bar.vsix

The overlay is fully functional without it. Installing it adds:

  • notifications suppressed while VS Code already has focus
  • prompts auto-acknowledged when you switch to VS Code to deal with them
  • a reliable target for [Open VS Code]
  • git branch, active file, and error/warning counts on the expanded card

It reads the token from the desktop app's own config file, so nothing secret is stored in VS Code settings or carried through Settings Sync. It never modifies project files.

Configuration

One file. No env vars.

OSConfig path
Windows%APPDATA%\Sidelong\config.json
macOS~/Library/Application Support/Sidelong/config.json
Linux~/.config/Sidelong/config.json
FieldDefaultPurpose
port47821Receiver port. Baked into installed hooks — changing it needs a reinstall.
tokenrandom 64 hexLocal shared secret, generated once then stable.
shortcutControl+Shift+SpaceGlobal show / minimize.
staleMs90000Silence after which a working session dims. Never changes its status.
completedDismissMs20000How long a finished turn stays expanded. 0 disables.
debugLogfalseOpt-in local logging. Off by default — payloads are sensitive.

The default shortcut collides with VS Code. Ctrl+Shift+Space is VS Code's Trigger Parameter Hints, and a global shortcut wins — so VS Code loses that binding while Sidelong runs. Change shortcut in the config; Ctrl+Alt+Space is unbound on a stock setup.

Troubleshooting

When it doesn't move.

SymptomCause & fix
Overlay never updatesRun node tools/install-hooks.mjs status. If allowedHttpHookUrls is set anywhere in your settings it silently gates HTTP hooks — the installer prints the exact URL to add. Also restart any session that was already running.
No window opensELECTRON_RUN_AS_NODE=1 is set by VS Code. Unset it and relaunch.
“Port 47821 is already in use”Deliberate — moving silently would orphan every installed hook, and hook failures are silent by design. Free the port, or accept the dialog's offer to move to 47822 and reinstall.
[Open VS Code] says “Install the VS Code bridge”There is no safe file to open yet and no bridge to name the active one. Install the extension. This is intentional: the alternative was opening a folder, which used to launch a new window and could evict the session.
Notifications fire while I'm in VS CodeFocus detection needs the bridge extension. Install it.
Did the overlay break my session?It cannot. Hook connection failures, timeouts and non-2xx responses are all non-blocking by design — tested by killing the app mid-session and confirming tool calls still ran at normal speed.

Removing it

Clean uninstall.

node tools/install-hooks.mjs uninstall                 # user scope
node tools/install-hooks.mjs uninstall --scope project
code --uninstall-extension sidelong.sidelong-claude-status-bar

Only entries whose URL starts with Sidelong's base URL are removed — nothing else in your settings is touched, and the pre-change backup is still there. Inside Claude Code, /hooks shows what remains and disableAllHooks turns everything off at once.
